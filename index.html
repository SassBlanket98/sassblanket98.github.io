Website & Booking Monitor

Medical client · no public demo

A Python and Playwright monitor checks an anonymised medical client's public website and patient booking system twice a day, then sends a report on Telegram. It exercises the booking flow and confirms test appointments are cleaned up. Cancellation matching uses appointment time, day and month when the portal displays a friendly date label.

//It regularly catches real problems on the booking platform: a broken booking flow, pages that were down or erroring, and test data that wasn't getting cleaned up. It reports failed booking and cancellation steps so they can be investigated.
//When something fails, the report says which step broke, who most likely needs to fix it, and what to do next, with the evidence attached.
//When a check fails, an LLM reads the failure and adds a root-cause comment to the report.
//It checks its own cleanup too, so a leftover test booking gets reported instead of missed.

Personal AI Stack

Self-hosted · daily use

The multi-agent setup I use every day for research, planning and general automation. It runs on OpenClaw, and memory is handled by MemPalace, an open source project. I added my own diary and checkpoint workflows on top.

The newest agent, Onyx, is my day-to-day assistant on Telegram, and it runs on a 9B model on my own GPU through llama.cpp. A model that small can't be trusted to plan and check code changes, so Onyx hands that work to a job pipeline that plans, builds, verifies and reviews with stronger models, and stops for my approval after the plan by default. The chat model runs locally, but messages also go to a hosted router and relevance judge. Notes marked private are never sent to either. I'm now building the test suite and training data to see whether fine-tuning the local model makes it a more reliable orchestrator.
